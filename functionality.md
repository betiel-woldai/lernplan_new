# Lernplaner - Functionality & Flow Guide

**Version:** 1.8.0
**Focus:** How features connect and data flows through the system

---

## Core Concept

The application follows this logical flow:
```
Subject → Calendar Sessions → Learning Sessions → XP/Stats → Level/Achievements
```

**The Big Picture:**
Users create subjects (e.g., "Mathematics") with weekly hour goals and exam dates. When they study, they track sessions with a timer. Completed sessions award XP (experience points) which increases their level and maintains their daily learning streak. The system automatically generates a study calendar and provides progress analytics.

## 1. Subject Management Flow

**💡 Core Idea:** Subjects are the foundation of the learning system. When you create a subject, the system automatically calculates how many total hours you need to study, generates a calendar schedule, and begins tracking your progress toward the exam goal.

### Creating a Subject

**User Action:** `/subjects` → "Add Subject" button

**Form Input:**
- Name, color, start date, exam date
- Hours per week (e.g., 8), Days per week (e.g., 4), Intensity weeks (e.g., 3)

**Backend Process (`POST /api/subjects`):**
```
1. Validate input (Zod schema)
2. Calculate targetHours = (weeksUntilExam * hoursPerWeek) + (intensityWeeks * hoursPerWeek * 1.5)
3. Insert into subjects table
4. Return subject with ID
```

**Automatic Connections:**

**→ Calendar Auto-Population:**
- System immediately generates calendar sessions
- Distribution: `hoursPerWeek / daysPerWeek = hours per day`
- Creates recurring study sessions until exam date
- Exam date gets blocked as "Exam" session type
- Intensity weeks get 1.5x multiplier for session frequency
- All sessions marked with `isAutoGenerated: true`, `sourceSubjectExamId`

**→ Dashboard Display:**
- Subject appears in subject cards list with color
- Shows progress: `0 / targetHours`
- Exam countdown timer starts
- Quick-start button becomes available

**→ Analytics Preparation:**
- Subject appears in analytics subject dropdown
- Pie chart includes subject (0% initially)
- Progress tracking initialized

## 2. Session Tracking Flow

**💡 Core Idea:** Sessions are actual study time you track with a timer. When you complete a session, it's the trigger point for everything: XP is calculated and awarded, your subject progress increases, your daily streak updates, and all statistics refresh. Think of session completion as the "heartbeat" that updates the entire system.

### Starting a Learning Session

**User Action:** Click play button on subject card OR "Start Session" button

**Session Modal:**
- Subject pre-selected (if from card) or selectable (if global)
- Duration options: 15/25/45/60/90/120 minutes
- Optional notes field

**On "Start Session":**

```
Frontend:
1. POST /api/sessions with { subjectId, duration, date, notes }

Backend (/api/sessions):
1. Create session record with completed: false
2. Calculate XP:
   - baseXP = (duration / 15) * 10
   - completionBonus = baseXP * 0.20 (if completed)
   - totalXP = baseXP + completionBonus (min 5)
3. Insert into learning_sessions table
4. Update user stats:
   - totalXP += sessionXP
   - dailyTime += duration
   - weeklyTime += duration
5. Update subject:
   - completedHours += (duration / 60)
6. Check and update streak:
   - If last session was yesterday: increment streak
   - If last session was today: maintain streak
   - If gap > 1 day: reset to 1
7. Log gamification_event
8. Return session + XP data

Frontend Event Chain:
1. Receive response with XP amount
2. Emit 'xpGained' event
3. XPToast displays "+{XP} XP"
4. Update local state
5. Check for level-up:
   - newLevel = floor(sqrt(totalXP / 100)) + 1
   - If level increased: trigger confetti + modal
6. Check for achievements:
   - Session count achievements
   - Time-based achievements
   - Streak achievements
7. Refresh all components via event bus
```

**Connections Triggered:**

**→ Calendar Updates:**
- Completed learning session appears on calendar
- Original auto-generated calendar session marked as completed (if exists)
- Visual opacity change (completed sessions = 50% opacity)

**→ Subject Card Updates:**
- Progress bar increases: `completedHours / targetHours`
- "Hours this week" counter increments
- Color-coded progress visualization

**→ Dashboard Stats Update:**
- Total time increases
- Session count increments
- Average duration recalculates
- XP bar animates to new value

**→ Analytics Impact:**
- "Progress Over Time" chart adds data point
- "Subject Distribution" pie chart updates percentages
- Session count in subject table increments
- Completion rate recalculates

**→ Gamification:**
- Level badge updates if level changed
- Streak counter updates with new intensity
- Achievement badges unlock if thresholds met
- Recent events list adds "Session completed" entry

## 3. Calendar Integration

**💡 Core Idea:** The calendar is a visualization layer that merges three different data sources into one unified view: (1) automatically generated study sessions from your subjects, (2) your completed learning sessions showing what you actually did, and (3) fixed academic calendar events like holidays and exam periods. This gives you a complete picture of planned vs. actual study time.

### How Calendar Combines Data

**Calendar displays 3 types of events:**

**Type 1: Auto-Generated Study Sessions** (from subjects)
- Source: Subject parameters (hours/week, days/week)
- Created: When subject is created/updated
- Endpoint: `POST /api/calendar/sync`
- Fields: `isAutoGenerated: true`, `sourceSubjectExamId: subjectId`
- Color: Inherits from subject
- Editable: Yes (can move/delete)

**Type 2: Completed Learning Sessions**
- Source: Finished sessions from timer
- Created: When session completes
- Endpoint: `POST /api/sessions` (automatically synced)
- Fields: `completed: true`, `actualDuration: X`
- Color: Inherits from subject
- Editable: No (historical data)

**Type 3: Fixed Terminplan Events**
- Source: Academic calendar (holidays, exam periods)
- Created: Via cron job or manual import
- Endpoint: `POST /api/cron/terminplan`
- Fields: `isFixed: true`, `fixedSource: 'terminplan'`
- Color: System defined
- Editable: No (official dates)

**Calendar Query (`GET /api/calendar`):**
```sql
SELECT * FROM calendar_sessions
WHERE user_id = $1
  AND start_time >= $2
  AND end_time <= $3
ORDER BY start_time ASC
```

**Merge Logic:**
- Fetch calendar_sessions (Type 1 + 3)
- Fetch learning_sessions (Type 2)
- Merge both arrays
- Sort by start_time
- Group by date for calendar grid display

## 4. Dashboard Page Flow

**💡 Core Idea:** The dashboard is your "command center" that loads on startup. It fetches your current stats (level, XP, streak), displays today's calendar events, and sets up real-time listeners. When anything happens elsewhere in the app (session completed, XP gained), the dashboard receives events and updates instantly without needing a page refresh.

### What Happens on Dashboard Load

**Component Hierarchy:**
```
Dashboard
├── DashboardHeader (user greeting, level badge)
├── CalendarSection (calendar grid + session details)
│   ├── Calendar (month/week/day view)
│   └── SessionDetails (clicked session info)
└── StatsSidebar (XP, streak, achievements)
    ├── XPBar (progress to next level)
    ├── StreakDisplay (daily streak counter)
    └── AchievementBadge list
```

**Data Loading Sequence:**
```
1. Fetch user data: GET /api/users/[id]
   → Returns: totalXP, currentLevel, streak, lastSessionDate

2. Fetch today's calendar events: GET /api/calendar?date=today
   → Returns: Today's sessions + terminplan events

3. Fetch recent achievements: GET /api/achievements/user/[id]
   → Returns: Unlocked achievements + progress

4. Check for terminplan popup:
   - If first visit today: show TodaysTerminplanModal
   - Display all today's events with motivational messages
   - User can dismiss individually or all

5. Event listeners:
   - Listen for 'sessionCompleted' → refresh calendar
   - Listen for 'xpGained' → update XP bar
   - Listen for 'streakUpdated' → update streak display
   - Listen for 'achievementUnlocked' → show notification
```

**Real-time Updates:**
- When session completes elsewhere: calendar refreshes
- When XP gained: XPBar animates
- When level-up: Confetti + Modal appears
- When achievement unlocked: Badge pulses + notification

## 5. Analytics Page Flow

**💡 Core Idea:** Analytics aggregates all your historical session data into visual charts and summary statistics. It answers questions like "How much did I study this month?", "Which subject am I focusing on most?", and "Am I maintaining consistency?". The backend runs SQL queries to group and summarize data, then Chart.js renders it visually.

### Data Aggregation

**Period Selection:** Week/Month/Year dropdown

**Data Fetch (`GET /api/analytics?period=month`):**

**Backend Aggregation:**
```javascript
// Progress Over Time (Line Chart)
SELECT
  DATE(date) as day,
  SUM(duration) as total_minutes,
  COUNT(*) as session_count,
  SUM(points) as total_xp
FROM learning_sessions
WHERE user_id = $1
  AND date >= $2
  AND date <= $3
GROUP BY DATE(date)
ORDER BY day

// Subject Distribution (Pie Chart)
SELECT
  s.name,
  s.color,
  SUM(ls.duration) as total_minutes,
  COUNT(ls.id) as session_count,
  s.completed_hours,
  s.target_hours
FROM subjects s
LEFT JOIN learning_sessions ls ON s.id = ls.subject_id
WHERE s.user_id = $1
GROUP BY s.id

// Summary Statistics
SELECT
  SUM(duration) as total_time,
  COUNT(*) as total_sessions,
  AVG(duration) as avg_duration,
  SUM(points) as total_xp,
  SUM(CASE WHEN completed THEN 1 ELSE 0 END) as completed_count
FROM learning_sessions
WHERE user_id = $1 AND date >= $2 AND date <= $3
```

**Chart Rendering:**
- Chart.js processes aggregated data
- Colors match subject colors
- Interactive tooltips show details
- Responsive sizing

## 6. Gamification Logic Connections

**💡 Core Idea:** Gamification motivates consistent learning through a video game-like progression system. Study time converts to XP (experience points), which accumulates to increase your level (1-99). Reaching certain milestones (session count, total hours, streak days, levels) unlocks achievements. It's a feedback loop: study → earn XP → level up → unlock achievements → feel motivated to study more.

### XP → Level → Achievements Flow

**XP Calculation (in `/api/sessions`):**
```javascript
const baseXP = Math.floor(duration / 15) * 10;
const completionBonus = completed ? Math.floor(baseXP * 0.20) : 0;
const totalXP = Math.max(baseXP + completionBonus, 5);
```

**Level Calculation (real-time):**
```javascript
const newLevel = Math.floor(Math.sqrt(user.totalXP / 100)) + 1;
if (newLevel > user.currentLevel) {
  // Trigger level-up event
  emitEvent('levelUp', { oldLevel: user.currentLevel, newLevel });
}
```

**Achievement Checks (triggered after session):**
```javascript
// Session count achievements
if (userSessionCount === 10) unlock("First 10 Sessions");
if (userSessionCount === 50) unlock("50 Sessions Master");

// Time-based achievements
if (totalHours >= 100) unlock("100 Hours Scholar");

// Streak achievements
if (currentStreak === 7) unlock("Week Warrior");
if (currentStreak === 30) unlock("Monthly Master");

// Level achievements
if (currentLevel === 10) unlock("Level 10 Reached");
```

**Event Bus Propagation:**
```
Session Complete
  → XP Awarded
    → Level Check
      → Achievement Check
        → UI Updates
          → Celebrations (confetti/toasts/modals)
```

## 7. Streak System Logic

**💡 Core Idea:** Streaks measure daily learning consistency. If you study at least once today and you studied yesterday, your streak increments by 1. If you miss a day, it resets to 0. The visual intensity (flame color/size) increases with longer streaks to provide visual feedback and motivation. It's inspired by apps like Duolingo that encourage daily habits.

### How Streaks Update

**Check on Session Completion:**
```javascript
const today = new Date();
const lastSession = user.lastSessionDate;

if (!lastSession) {
  // First session ever
  streak = 1;
} else {
  const daysSinceLastSession = differenceInDays(today, lastSession);

  if (daysSinceLastSession === 0) {
    // Same day - maintain streak
    streak = user.currentStreak;
  } else if (daysSinceLastSession === 1) {
    // Yesterday - increment streak
    streak = user.currentStreak + 1;
  } else {
    // Gap > 1 day - reset streak
    streak = 1;
  }
}

// Update user
UPDATE users SET
  current_streak = streak,
  last_session_date = today
WHERE id = userId;
```

**Visual Intensity Mapping:**
```javascript
function getStreakIntensity(streak) {
  if (streak === 0) return 'gray';
  if (streak <= 2) return 'orange-weak';
  if (streak <= 6) return 'orange-medium';
  if (streak <= 13) return 'red-strong';
  if (streak <= 29) return 'red-intense';
  return 'purple-legendary'; // 30+
}
```

**Flame Icon Changes:**
- 0: No flame
- 1-6: Single flame
- 7-13: Double flames
- 14-29: Triple flames with glow
- 30+: Animated legendary flames

## 8. Terminplan Integration

**💡 Core Idea:** Terminplan (academic calendar) integrates official university dates like semester start/end, exam periods, and holidays. These are "fixed" events that can't be edited by users. A cron job checks for updates to the academic calendar data and syncs changes. On the dashboard, users get a daily popup showing today's important academic events with motivational messages.

### How Academic Calendar Integrates

**Data Source:** Fixed JSON/config with semester dates

**Cron Job Process:**
```
1. GET /api/cron/terminplan (dry-run)
   → Calculates checksum of current terminplan data
   → Compares with stored checksum
   → Returns: { added: X, modified: Y, removed: Z }

2. User reviews changes in Admin UI

3. POST /api/cron/terminplan (apply)
   → Inserts new events with isFixed: true
   → Updates changed events
   → Deletes removed events
   → Updates checksum
```

**Popup Logic (Dashboard):**
```javascript
// On dashboard load
const todaysEvents = await fetchTodaysTerminplan();
const dismissedEvents = getFromLocalStorage('dismissedTerminplan');

const eventsToShow = todaysEvents.filter(
  event => !dismissedEvents.includes(event.id)
);

if (eventsToShow.length > 0) {
  showTodaysTerminplanModal(eventsToShow);
}
```

**Event Types with Messages:**
- Semester Start: "Neues Semester beginnt! 🎓"
- Exam Registration: "Prüfungsanmeldung läuft! ⏰"
- Exam Period: "Prüfungsphase - du schaffst das! 💪"
- Holidays: "Frohe Weihnachten! 🎄" / "Schöne Osterferien! 🐰"

## 9. Component Communication

**💡 Core Idea:** The event bus is a messaging system that allows different parts of the application to communicate without being directly connected. When something important happens (session completed, XP gained), an event is "broadcast" and any component listening for that event can react. This keeps components loosely coupled while maintaining real-time synchronization across the entire UI.

### Event Bus Pattern

**Custom Event Emitter:**
```javascript
// src/lib/eventBus.ts
const eventBus = {
  emit(event, data) {
    window.dispatchEvent(new CustomEvent(event, { detail: data }));
  },
  on(event, callback) {
    window.addEventListener(event, (e) => callback(e.detail));
  }
};
```

**Event Flow Example:**
```
User completes session
  ↓
POST /api/sessions succeeds
  ↓
eventBus.emit('sessionCompleted', { sessionId, xp, subjectId })
  ↓
[Multiple listeners react]
  → Calendar: refresh calendar data
  → Dashboard: update stats sidebar
  → SubjectCard: update progress bar
  → XPBar: animate to new value
  → Achievements: check for unlocks
```

**Key Events:**
- `sessionCompleted` - Session finished
- `xpGained` - XP awarded
- `levelUp` - Level increased
- `achievementUnlocked` - New achievement
- `streakUpdated` - Streak changed
- `subjectUpdated` - Subject edited
- `calendarRefresh` - Calendar needs reload

## 10. Data Consistency

**💡 Core Idea:** Data consistency means when a session completes, multiple database tables need to update simultaneously (user stats, subject progress, streak, etc.). Database transactions ensure it's "all or nothing": either all updates succeed together, or if anything fails, everything rolls back to prevent partial/corrupted data. This maintains integrity across the entire system.

### How Stats Stay Synchronized

**Transaction Pattern (in `/api/sessions` POST):**
```javascript
await client.query('BEGIN');
try {
  // 1. Insert session
  const session = await insertSession({ subjectId, duration, xp });

  // 2. Update user stats
  await updateUserStats({
    totalXP: user.totalXP + xp,
    dailyTime: user.dailyTime + duration,
    sessionCount: user.sessionCount + 1
  });

  // 3. Update subject progress
  await updateSubject({
    completedHours: subject.completedHours + (duration / 60)
  });

  // 4. Update streak
  await updateStreak({ lastSessionDate: now, streak: newStreak });

  // 5. Log event
  await insertGamificationEvent({
    type: 'session_completed',
    xp,
    metadata: { sessionId: session.id }
  });

  await client.query('COMMIT');
} catch (error) {
  await client.query('ROLLBACK');
  throw error;
}
```

**Recalculation Endpoint (`POST /api/gamification/recalculate`):**
```javascript
// Recalculate total XP from all sessions
const totalXP = await sumAllSessionXP(userId);
const newLevel = calculateLevel(totalXP);

await updateUser({
  totalXP,
  currentLevel: newLevel
});
```
